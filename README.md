# thrtythr.shop — интернет-магазин на Next.js и Supabase

`thrtythr.shop` — учебно-практический проект интернет-магазина одежды, обуви и аксессуаров. Проект реализован как полноценное web-приложение: есть публичный каталог, карточки товаров, корзина, оформление заказов, личный кабинет покупателя, избранное, административная панель, аналитика, загрузка изображений и работа с реальной базой данных Supabase.

Документ написан подробно, чтобы по нему можно было понять устройство проекта, объяснить его на защите дипломной работы и быстро разобраться, за что отвечает каждый основной файл.

---

## 1. Назначение проекта

Главная цель проекта — разработать современный интернет-магазин с разделением на клиентскую и административную части.

Покупатель может:

- просматривать главную страницу и каталог;
- открывать карточку товара;
- добавлять товары в корзину;
- оформлять заказ;
- регистрироваться и входить в личный кабинет;
- восстанавливать пароль через код из email;
- добавлять товары в избранное;
- видеть историю своих заказов и их актуальные статусы.

Администратор может:

- входить в админ-панель;
- добавлять, редактировать и архивировать товары;
- загружать изображения товаров в Supabase Storage;
- просматривать заказы;
- менять статус заказа и статус оплаты;
- просматривать клиентов;
- видеть графики дохода, топ товаров и товары с низким остатком;
- экспортировать заказы в CSV.

## 3. Быстрый запуск проекта

### Установка зависимостей

```bash
npm install
```

### Запуск в режиме разработки

```bash
npm run dev
```

После запуска сайт будет доступен по адресу:

```text
http://localhost:3000
```

```bash
npm run build
```

```bash
npm run start
```

Для хостинга обычно используются команды:

```bash
npm install && npm run build
```

Start command:

```bash
npm run start
```

## 4. Переменные окружения

Для корректной работы проекта нужны переменные окружения.

```env
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
SUPABASE_STORAGE_BUCKET=products

ADMIN_LOGIN=...
ADMIN_PASSWORD=...
ADMIN_SESSION_SECRET=...
```

### Что означает каждая переменная

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | URL Supabase-проекта. Используется и клиентом, и сервером |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Публичный ключ Supabase для браузера |
| `SUPABASE_SERVICE_ROLE_KEY` | Секретный серверный ключ Supabase. Нельзя отдавать в браузер |
| `SUPABASE_STORAGE_BUCKET` | Bucket для изображений товаров, обычно `products` |
| `ADMIN_LOGIN` | Логин администратора |
| `ADMIN_PASSWORD` | Пароль администратора |
| `ADMIN_SESSION_SECRET` | Секрет для защиты административной сессии |

## 6. Папка `app` — страницы и API приложения

Папка `app` используется Next.js App Router. В ней находятся как обычные страницы сайта, так и серверные API-маршруты.

Пример соответствия файлов и URL:

```text
app/products/page.tsx      → /products
app/account/page.tsx       → /account
app/admin/orders/page.tsx  → /admin/orders
app/api/products/route.ts  → /api/products
```

---

## 7. Основные страницы сайта

### `app/layout.tsx`

Главный layout приложения. Он оборачивает все страницы сайта и подключает общие элементы.

Обычно через layout подключаются:

- глобальные стили;
- общий контекст приложения;
- шапка сайта;
- корзина;
- мобильная навигация;
- базовая HTML-структура.

Этот файл нужен, чтобы не дублировать одинаковые элементы на каждой странице.

---

### `app/page.tsx`

Главная страница интернет-магазина.

На ней размещаются:

- hero-блок с названием и позиционированием магазина;
- подборки товаров;
- карусель или блок хитов продаж;
- ссылки на каталог;
- визуальные блоки для первого впечатления пользователя.

Главная страница нужна для презентации магазина и быстрого перехода к покупкам.

---

### `app/products/page.tsx`

Страница каталога товаров.

Функции страницы:

- загрузка товаров из `/api/products`;
- отображение карточек товаров;
- фильтрация по категориям;
- вывод новинок, хитов и обычных товаров;
- переход на страницу конкретного товара.

Важно: товары не зашиты в коде. Они берутся из Supabase.

---

### `app/product/page.tsx`

Страница одного товара.

На ней пользователь видит:

- название товара;
- цену;
- фотографии;
- описание;
- размеры;
- остаток;
- кнопку добавления в корзину;
- информацию о товаре.

Эта страница нужна для детального просмотра товара перед покупкой.

---

### `app/checkout/page.tsx`

Страница оформления заказа.

Здесь пользователь вводит данные доставки:

- имя;
- телефон;
- email;
- город;
- адрес;
- комментарий.

Если пользователь вошёл в аккаунт, часть данных может подставляться из профиля.

После отправки формы заказ создаётся через API `/api/orders`.

---

### `app/checkout/success/page.tsx`

Страница успешного оформления заказа.

После создания заказа пользователь видит номер заказа, например:

```text
THR-714652-65
```

Этот номер также отображается в админке и личном кабинете.

---

### `app/not-found.tsx`

Кастомная 404-страница.

Она показывается, если пользователь открыл несуществующий адрес. Наличие красивой 404-страницы важно для production-качества сайта.

## 8. Авторизация и личный кабинет

### `app/register/page.tsx`

Страница регистрации покупателя.

Порядок работы:

1. Пользователь вводит имя, email, телефон и пароль.
2. Сайт проверяет через `/api/auth/email-exists`, свободна ли почта.
3. Если email свободен, Supabase отправляет код подтверждения на почту.
4. Пользователь вводит код на сайте.
5. После подтверждения создаётся аккаунт и профиль.

Телефон сохраняется в таблицу `profiles`.

---

### `app/login/page.tsx`

Страница входа пользователя.

Пользователь вводит email и пароль. При успешном входе открывается личный кабинет `/account`.

Ошибки авторизации переводятся на русский или казахский язык через `lib/authMessages.ts`.

---

### `app/forgot-password/page.tsx`

Страница восстановления пароля.

Порядок работы:

1. Пользователь вводит email.
2. Supabase отправляет код восстановления.
3. Пользователь вводит код и новый пароль.
4. Пароль обновляется.

Такой сценарий удобнее, чем техническая ссылка из письма, потому что пользователь остаётся на сайте и вводит код в понятную форму.

---

### `app/account/page.tsx`

Личный кабинет покупателя.

В личном кабинете отображаются:

- email пользователя;
- имя;
- телефон;
- город;
- адреса доставки;
- история заказов;
- избранные товары;
- кнопка выхода.

История заказов обновляется автоматически. Если администратор изменит статус заказа, пользователь увидит изменение в личном кабинете.

Статусы отображаются не техническими словами `new` и `pending`, а нормальными подписями:

```text
Новый заказ
Ожидает оплаты
В обработке
Отправлен
Доставлен
```

Для казахского языка используются отдельные переводы.

## 10. API-маршруты

API-маршруты находятся в `app/api`. Они выполняются на сервере и работают с Supabase через защищённый server-side client.

---

### `app/api/products/route.ts`

Публичный API получения товаров.

Он:

- подключается к Supabase;
- получает активные товары;
- исключает удалённые товары;
- сортирует товары;
- возвращает данные клиенту.

Этот API используется каталогом, главной страницей и карточками товаров.

---

### `app/api/orders/route.ts`

API создания заказа.

Он принимает данные из checkout-формы и создаёт:

- клиента;
- заказ;
- позиции заказа.

Если пользователь авторизован, заказ связывается с `user_id`. Благодаря этому заказ появляется в личном кабинете.

---

### `app/api/auth/email-exists/route.ts`

API проверки email перед регистрацией.

Он нужен, чтобы не позволять регистрировать один и тот же email несколько раз.

Проверка выполняется через Supabase Admin API.

---

### `app/api/account/profile/route.ts`

API профиля покупателя.

Методы:

- `GET` — получить профиль;
- `PATCH` — обновить профиль.

Работает с таблицей `profiles`.

---

### `app/api/account/addresses/route.ts`

API адресов покупателя.

Позволяет:

- получить адреса;
- добавить адрес;
- изменить адрес;
- удалить адрес.

Адреса хранятся в таблице `customer_addresses`.

---

### `app/api/account/wishlist/route.ts`

API избранного.

Позволяет:

- получить список избранных товаров;
- добавить товар в избранное;
- удалить товар из избранного.

Данные хранятся в таблице `wishlist_items`.

---

### `app/api/account/orders/route.ts`

API заказов покупателя.

Возвращает только заказы текущего авторизованного пользователя.

Используется в блоке `История заказов` в личном кабинете.

---

### `app/api/admin/products/route.ts`

Админский API управления товарами.

Поддерживает:

- получение товаров;
- создание товара;
- редактирование товара;
- архивирование товара.

Работает с таблицами:

- `products`;
- `product_images`;
- `product_sizes`;
- `categories`.

---

### `app/api/admin/upload/route.ts`

API загрузки изображений.

Файл отправляется в Supabase Storage, после чего API возвращает публичную ссылку на изображение.

Это нужно, чтобы администратор мог добавлять реальные фото товаров без ручной загрузки в базу.

---

### `app/api/admin/orders/route.ts`

Админский API заказов.

Используется для:

- получения списка заказов;
- изменения статуса заказа;
- изменения статуса оплаты.

---

### `app/api/admin/orders/export/route.ts`

API экспорта заказов в CSV.

Полезен для отчётности и ручной обработки заказов.

---

### `app/api/admin/customers/route.ts`

API клиентов.

Возвращает список клиентов из Supabase.

---

### `app/api/admin/stats/route.ts`

API статистики админки.

Считает:

- общий доход;
- количество заказов;
- количество клиентов;
- количество товаров;
- средний чек;
- доход по дням;
- топ товаров;
- товары с низким остатком;
- товары без фото.

Этот API используется страницами `/admin` и `/admin/analytics`.

## 12. Папка `lib`

Папка `lib` содержит вспомогательную логику, типы, переводы и подключение к Supabase.

---

### `lib/context.tsx`

Глобальный контекст приложения.

Хранит:

- текущий язык `RU` или `KZ`;
- товары в корзине;
- количество товаров;
- итоговую сумму;
- состояние открытия корзины;
- функции добавления и удаления товаров.

Корзина сохраняется в `localStorage`, поэтому товары не исчезают после обновления страницы.

---

### `lib/types.ts`

Файл TypeScript-типов.

Описывает структуры данных:

- товар;
- категория;
- размер;
- корзина;
- заказ;
- элемент заказа;
- данные checkout-формы.

Типы делают код понятнее и уменьшают количество ошибок.

---

### `lib/authMessages.ts`

Файл локализации ошибок авторизации.

Supabase может возвращать технические сообщения на английском, например:

```text
email rate limit exceeded
invalid login credentials
```

Этот файл превращает их в понятные сообщения:

```text
Слишком много писем отправлено подряд. Подождите 1–2 минуты и попробуйте снова.
Неверный email или пароль.
```

Также есть казахские варианты.

---

### `lib/orderLabels.ts`

Файл перевода статусов заказов и оплат.

В базе хранятся технические значения:

```text
new
processing
shipped
delivered
pending
paid
```

В интерфейсе показываются понятные подписи:

```text
Новый заказ
В обработке
Отправлен
Доставлен
Ожидает оплаты
Оплачен
```

Такой подход удобен, потому что база остаётся стабильной, а интерфейс можно переводить.

---

### `lib/supabase/client.ts`

Supabase-клиент для браузера.

Используется в клиентских страницах:

- регистрация;
- вход;
- восстановление пароля;
- получение текущей сессии;
- работа с пользовательским токеном.

Этот клиент использует публичный publishable key.

---

### `lib/supabase/server.ts`

Supabase-клиент для сервера.

Используется в API-маршрутах.

Работает с `SUPABASE_SERVICE_ROLE_KEY`, поэтому имеет доступ к операциям, которые нельзя выполнять из браузера.

Например:

- создание заказов;
- получение статистики;
- проверка email;
- загрузка файлов;
- админские операции.

---

### `lib/supabase/auth.ts`

Серверные функции проверки пользователя.

Файл достаёт Bearer-токен из запроса и проверяет его через Supabase.

Это нужно для защищённых API личного кабинета.

### `lib/supabase/products.ts`

Функции преобразования товаров из Supabase.

В Supabase товар может приходить вместе с вложенными данными:

- категория;
- изображения;
- размеры.

Этот файл превращает данные базы в удобный объект товара для интерфейса.

## 13. Папка `supabase`

Папка содержит SQL-файлы для настройки базы данных.

Основная схема базы данных.

## 15. Как работает оформление заказа

1. Пользователь добавляет товар в корзину.
2. Корзина хранится в `lib/context.tsx` и `localStorage`.
3. Пользователь открывает checkout.
4. Форма отправляет данные в `/api/orders`.
5. API создаёт запись в `customers`.
6. API создаёт запись в `orders`.
7. API создаёт позиции в `order_items`.
8. Если пользователь вошёл, заказ получает `user_id`.
9. Заказ появляется в админке и личном кабинете.

---

## 16. Как работает личный кабинет

1. Пользователь регистрируется через Supabase Auth.
2. После подтверждения email создаётся профиль в `profiles`.
3. Пользователь входит через `/login`.
4. Страница `/account` получает профиль, адреса, заказы и избранное через API.
5. Заказы обновляются автоматически.
6. При выходе сессия очищается.

---

## 17. Как работает избранное

1. Пользователь нажимает сердечко на товаре.
2. Если он не вошёл, сайт отправляет его на страницу входа.
3. Если вошёл, товар добавляется в `wishlist_items`.
4. В личном кабинете отображается список избранных товаров.

---

## 18. Как работает админка

1. Администратор входит через `/admin/login`.
2. После входа доступны разделы админки.
3. Товары управляются через `/admin/products`.
4. Заказы управляются через `/admin/orders`.
5. Аналитика строится через `/api/admin/stats`.
6. Изображения загружаются в Supabase Storage.

---

## 19. Как работают графики

Графики в админке строятся по реальным заказам.

API `/api/admin/stats` берёт данные из таблиц:

- `orders`;
- `order_items`;
- `products`;
- `customers`.

После этого API считает:

- доход по дням;
- количество заказов;
- средний чек;
- топ товаров;
- товары с низким остатком.

Графики обновляются каждые 10 секунд.

---

## 20. Как работает загрузка изображений

1. Администратор выбирает файл изображения.
2. Файл отправляется в `/api/admin/upload`.
3. API загружает изображение в Supabase Storage.
4. Supabase возвращает публичную ссылку.
5. Ссылка сохраняется в товаре.
6. Сайт отображает картинку товара.

## 22. Настройка Supabase Auth для email-кодов

Для регистрации и восстановления пароля через код нужно настроить email-шаблоны Supabase.

В шаблоне подтверждения регистрации используется:

```html
<h2>Код подтверждения / Растау коды</h2>
<p>Введите этот код на сайте:</p>
<h1>{{ .Token }}</h1>
<p>Если вы не регистрировались, просто игнорируйте это письмо.</p>
```

В шаблоне восстановления пароля:

```html
<h2>Восстановление пароля / Құпиясөзді қалпына келтіру</h2>
<p>Введите этот код на сайте:</p>
<h1>{{ .Token }}</h1>
<p>Если вы не запрашивали восстановление, просто игнорируйте письмо.</p>
```

Также желательно установить длину OTP-кода:

```text
mailer_otp_length = 6
```

## 24. Почему проект разделён именно так

Проект разделён на уровни:

```text
app          → страницы и API
components   → переиспользуемый интерфейс
lib          → бизнес-логика, типы, Supabase, переводы
supabase     → SQL-схема базы
public       → статические файлы
```

Такой подход удобен, потому что:

- проще искать нужный код;
- каждый файл отвечает за свою задачу;
- легче расширять проект;
- можно отдельно менять интерфейс, API и базу;
- проект выглядит как настоящее production-приложение.
